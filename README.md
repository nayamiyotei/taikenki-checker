# 合格体験記 一次チェックツール

合格体験記の「アンケート」「本文」を、ルールエンジンとAI（Gemini）で一次チェックし、タイトル案も作るツールです。画像編集は含まれません（別ツール）。

> **このツールは「下見」です。** 指摘はすべて候補で、採用するかどうかの最終判断は、必ず編集担当者が行います。

---

## 1. ファイル構成

```
checker/
├── index.html
├── css/style.css          桜デザイン（ライト／夜桜ダーク。「テーマ」ボタンで切替）
└── js/
    ├── rules.js           ルール定義。ルールの追加・変更は、基本ここだけ
    ├── rule-engine.js     ルールエンジン（AIに頼らず、コードで確実に検出する部分）
    ├── gemini-client.js   Gemini API との通信（再試行・モデル自動切替）
    ├── logger.js          利用の記録・エラーの記録（Googleスプレッドシート）
    └── app.js             画面操作・AIへの指示文・結果表示
```

---

## 2. 使い方（画面の流れ）

| タブ | 内容 |
|---|---|
| **00 一括** | 管理画面の表示をそのまま貼り付け。「アンケート結果」「本文」の見出し行で自動的に分かれる。「3つをまとめてチェック」または「ルールのみ（送信なし）」。結果の下に「管理画面へ入力（コピー）」欄 |
| **01 アンケート** | 「項目に分割」→「AIでチェック」。「掲載する」の行を項目の区切りにする |
| **02 本文を校正** | 本文を貼って「AIでチェック」。指摘箇所はプレビューでハイライト |
| **03 タイトル案** | 本文を貼って「タイトル案を生成」。20字以内が理想、長くても30字以内 |

### 設定（画面上部）
- **Gemini APIキー**：ブラウザには保存されません（ページを閉じると消える）。毎回入力。取得は [Google AI Studio](https://aistudio.google.com/apikey)
- **モデル**：初期値は `gemini-3.5-flash-lite`（高速・標準）。混み合ったときは、ほかのモデルを自動で試します（下記）
- **あなたの名前**：利用記録用。この端末にだけ保存

### 指摘カードの見方
- **ルールエンジン（確実）**：ほぼ正しい指摘（NG講師名、講座名・用語の表記、数字の全角/半角、句読点、模試の難しさの書き方など）
- **AI判断**：参考意見。間違うことがある。根拠・文脈・影響を確認してから判断する
- **講座名の確認（要確認）**：削除ではなく、東進の公式ページで正式名称を調べる指摘
- **採用／不採用／要相談**：採用した指摘だけが「修正後の本文」に反映される。「すべて採用」「未判断を不採用に」「元に戻す」も使える
- 文字数は自動表示のみ。超えてもエラーにはならない

---

## 3. チェックの中身

### ルールエンジンが確実に処理するもの（AIに頼らない）
- 数字の全角/半角（**1桁は全角、2桁以上は半角**。「12月」の「1」だけを見るような誤検出はしない）
- NG講師名
- コンテンツ名・用語の表記統一（辞書にあるもの）。長い名前と短い名前が重なる場合は、長いほうだけを指摘
- 句読点（「，」→「、」など）
- **模試の難しさ**：「本番より難度が高い」「本番より何度が高い」「本番より難しい」などを検出し、「本番と同じレベル」への書き換えを提案（掲載しない決まりのため）

### AIが判断するもの（`rules.js` の文面でAIに指示）
- 削除対象（第一志望不合格、競合他社の名前、授業のネタバレ、友人の実名 など）
- 文体・表記（語尾の統一、誤字脱字、ら抜き言葉 など）
- アンケート特有のルール（「なし」回答、活動日数、引退時期 など）

### AIの誤りを減らす後処理（`rule-engine.js`）
- `<br>` などのHTMLタグの除去、本文にない文字を写した指摘の除外
- 語尾の指摘は、少数派の文だけ残す（全体が統一されていれば出さない）
- 二次試験の話を共通テストに直そうとする指摘の除外
- ルールエンジンの指摘とAIの指摘が重なるときは、ルールエンジン側を優先

### 友人の実名
友人の個人名が書かれている場合は、伏せ字（〇〇）にせず、「友人」「友達」など、**名前を使わない単なる友人としての表現**に書き換える案を出します。担任・担任助手への言及は、そのままで構いません。

---

## 4. 個人情報の扱い

- **AIチェックを使うと、貼った文章がGoogle（Gemini API）に送信されます。** 送る前に、生徒名・高校名・友人の実名など、個人が特定できる部分を、自分で確認して伏せ字にしてください（初期設定では、「伏せ字にしました」にチェックを入れるまでAIチェックを実行できません）
- **「ルールのみ（送信なし）」は、どこにも送信しません**
- 利用記録に残るのは、名前・日時・ツール名・機能・件数だけです。**体験記の本文は記録されません**
- APIキーは、人に教えない・画面共有やスクリーンショットに写さない

---

## 5. 混み合い・上限（503／429／400）への対応

| エラー | 意味 | ツールの動き／対処 |
|---|---|---|
| **503** など（500/502/504） | Google側の混雑 | 同じモデルで最大2回（2秒・4秒）やり直し → 別のモデルを順に試す（画面に状況を表示） |
| **429** | 無料枠の上限（1分または1日） | すぐ別のモデルへ。全部だめなら、1〜2分あけて再実行。1日の上限なら翌日 |
| **400** | 依頼の形式やAPIキーの問題 | タイトル案では、「考える時間を減らす設定」を外して1回やり直す。APIキーが違うときは、入力し直す |
| 404 | モデル名が廃止された | 「モデル」欄の value（`index.html` の `<option>`）を、新しい名前に変える |

- 予備のモデルは、「モデル」欄の選択肢のうち、選んでいないもの（proを除く）
- 1回の通信は40秒で打ち切ります
- **タイトル案**：AIが使えないときは、本文から15〜35字の区切りを機械的に抜き出した案を出します（「AIなし・目安」と表示。意味が通るか、自分で確認すること）
- 無料枠は、混み合う時間帯に後回しにされやすく、503が続くことがあります。安定させたい場合は、Google AI Studio で課金（有料枠）を有効にする方法があります（費用は部で判断）
- 失敗した呼び出しも、無料枠の回数に数えられる可能性があります（Googleは明言していません）。連打せず、数分あけて押してください

## 6. 利用の記録・エラーの通知（Googleスプレッドシート／メール）

利用状況の集計と、エラーのメール通知は、Google Apps Script（GAS）のウェブアプリで行います。

- 記録される項目：名前・日時・ツール名・機能・件数（＋エラーのときは、エラー文の先頭150字）
- 同じスプレッドシートの中で、シートを分けます：**「利用ログ」**（正常に使った記録）と **「エラー」**（エラーの記録）
- エラーが出たとき、指定したメールアドレスに通知します

### 設定手順
1. 新しいスプレッドシートを作る →「拡張機能」→「Apps Script」
2. 次のコードを貼り付けて保存（`NOTIFY_TO` を、通知を受け取りたいメールアドレスに変える）

```js
const NOTIFY_TO = "ここに通知先のメールアドレス";

function doPost(e) {
  const d = JSON.parse(e.postData.contents);
  const ss = SpreadsheetApp.getActiveSpreadsheet();
  const isError = String(d.action || "").indexOf("エラー") === 0;
  const name = isError ? "エラー" : "利用ログ";
  let sh = ss.getSheetByName(name);
  if (!sh) sh = ss.insertSheet(name);
  if (sh.getLastRow() === 0) sh.appendRow(["日時", "名前", "ツール", "機能", "件数", "詳細"]);
  sh.appendRow([new Date(d.ts), d.name, d.tool, d.action, d.count, d.detail || ""]);
  if (isError) {
    MailApp.sendEmail(NOTIFY_TO, "【一次チェックツール】エラー: " + d.action,
      "名前: " + d.name + "\n日時: " + new Date(d.ts) + "\n機能: " + d.action + "\n詳細: " + (d.detail || ""));
  }
  return ContentService.createTextOutput("ok");
}
```

3. 「デプロイ」→「新しいデプロイ」→ 種類「ウェブアプリ」／実行ユーザー「自分」／アクセスできるユーザー「全員」→ デプロイ。最初に許可（承認）を求められるので、許可する
4. 表示された URL を、`js/logger.js` の `LOG_URL` に貼る。空のままなら、記録はオフ
5. **コードを書き換えたときは、「デプロイ」→「デプロイを管理」→ 鉛筆アイコン →「新しいバージョン」で、再デプロイが必要**（保存しただけでは反映されません）

> お手元で、すでに動いているGASのコードがある場合は、そちらを優先してください。上のコードは、仕組みの例です。
> URL を知っている人は、誰でも書き込めます。URL は、社外に出さないでください。
> `doPost` をエディタから直接実行すると、`postData` がなくてエラーになります（正常です。テストは、ツールから行うか、テスト用の関数を作ってください）。

## 7. ルールの変更

- **表記のゆれ・NG講師名・コンテンツ名の追加**：`rules.js` の `LITERAL_RULES`（`ngTeachers` / `contentNamePairs` / `wordPairs` など）。ここに足した項目は、AIの調子に関係なく、確実に検出されます
- **AIに判断させたいルールの追加**：`rules.js` の `RULES`（`deleteItems` / `styleRules` / `surveyRules` / `titleRules`）
- **講座名の確認リンク**：`rules.js` の `COURSE_LIST_URL` に、東進の講座名が載っているページの URL を入れる
- **ルールエンジンの自己テスト**：画面の「ルール自己テスト」ボタンで実行（現在18件。全部「PASS」になるのが正常）
- **管理画面の貼り付け形式が違うとき**：`app.js` の `HEADS`（見出し行の正規表現）を直す

## 8. 公開方法（Cloudflare Pages）

1. このフォルダの中身を、GitHub のリポジトリに置く
2. Cloudflare Pages で、そのリポジトリを公開する（ビルド不要の静的サイト）
3. ID・パスワード認証（`functions/_middleware.js`）を、リポジトリのルートに置いたままにする
4. ファイルを更新したら、コミットして反映を待つ。ブラウザは、強制再読み込み（Windows：`Ctrl + Shift + R`）で、古いファイルを読み直す

---

## 9. 困ったとき

- **画面上部のボタンが反応しない／自己テストが出ない**：JavaScript の文法エラーの可能性が高いです。`F12` → Console で、赤いエラーの行番号を確認してください（`js/app.js` や `js/rule-engine.js` の貼り付けミス、カンマ抜けなど）
- **AIチェックでエラーが続く**：画面に出たエラー文（先頭の `APIエラー（番号）`）で、上の「5. 混み合い・上限」の表を確認
- それでも解決しないとき：画面とエラー文（個人情報は隠して）を、体験記リーダーに Slack で連絡
